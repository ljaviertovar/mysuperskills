# Stack notes: current patterns vs old patterns

Version-specific details for Next.js and Zod. Check the project's `package.json`, and use the *current*
column unless the project is pinned to an older major.

## Contents

- [Next.js](#nextjs)
- [Zod](#zod)

## Next.js

### Current (16.x)

- **Async request APIs only.** `params`, `searchParams`, `cookies()`, `headers()` must be awaited; sync access
  was removed in 16.
- **Typed handler context.** Type the second argument as `RouteContext<'/api/v1/meal-plans/[id]'>`. It is a
  global type generated by `next dev`, `next build` or `next typegen` (run `next typegen` before `tsc` in CI),
  and it rejects route literals that don't exist.
- **`proxy.ts`** replaces `middleware.ts`. It runs on the Node.js runtime only (`runtime` config is an error).
  Use it for cross-cutting concerns (CORS on `/api/v*`, session refresh); keep authorization in the handler.
- **Cache Components** (`cacheComponents: true`): GET handlers run at request time but may be prerendered if
  they touch no runtime data. Route segment configs `dynamic`, `revalidate`, `fetchCache` are not allowed;
  caching is opted into with `'use cache'` + `cacheLife()` inside helper functions (not in the handler body).
  **Never** put `'use cache'` on anything that reads tenant data, the session, or per-user results.
- **`after()`** from `next/server` runs work after the response is sent (logs, metrics, analytics). It throws
  outside a request scope, so wrap it (see `withApi`).
- **Route Handlers have no body size limit.** Enforce one in the parser (`parseJsonBody` does).
- **`export const maxDuration = 30`** (seconds) sets the platform limit per route. Route segment config must be a
  literal Next.js can analyze statically, so it can't be imported from `src/config/api.ts`; keep it above
  `apiConfig.timeouts.handlerMs`.
- **CSRF:** Next.js checks `Origin` against the host for Server Actions, but Route Handlers get no automatic
  protection; `withApi` adds it for cookie-authenticated mutations.
- **Server Functions (Server Actions)** are reachable by direct POST; page-level auth doesn't cover them.
  Authenticate, authorize and Zod-validate inside every one.

### Old patterns

- Next 15: `params` was a Promise but sync access still worked with a warning; handlers typed the context by
  hand (`{ params: Promise<{ id: string }> }`).
- Next ≤14: `params` was a plain object; GET handlers were cached by default (15 made them uncached).
- `middleware.ts` (deprecated name; only still needed if you require the edge runtime).
- `export const dynamic = 'force-static'` (not allowed with Cache Components).

## Zod

### Current (4.x)

- Objects: `z.strictObject({...})` for write bodies (unknown keys rejected), `z.object` for responses.
- Formats are top-level: `z.uuid()`, `z.email()`, `z.iso.date()`, `z.iso.datetime({ offset: true })`, `z.int()`.
- **`.partial()` does not neutralize `.default()`**: an absent field inside `.optional()` still receives its
  default. Never build a PATCH schema as `createSchema.partial()` when the create schema has defaults; write the
  update schema explicitly from shared field schemas.
- `z.unknown()` / `z.any()` object keys are required since 4.4; add `.optional()` if absence is allowed.
- JSON Schema: `z.toJSONSchema(schema, { io: 'input' | 'output', target: 'openapi-3.0' })`; metadata with
  `.meta({ id, description, examples })`, which is per instance (call it last).
- Errors: `error.issues` (stable), `z.flattenError()` / `z.treeifyError()` for nested shapes.

### Old patterns (Zod 3)

| Zod 4 | Zod 3 |
|---|---|
| `z.strictObject({...})` | `z.object({...}).strict()` |
| `z.uuid()` | `z.string().uuid()` |
| `z.iso.date()` | `z.string().date()` |
| `z.iso.datetime({ offset: true })` | `z.string().datetime({ offset: true })` |
| `z.int()` | `z.number().int()` |
| `z.toJSONSchema()` | `zod-to-json-schema` / `@asteasolutions/zod-to-openapi` |
| `error.issues` / `z.flattenError(err)` | `error.issues` / `err.flatten()` |
